===============================================================================
                           1. VIEW_ALUNOS
===============================================================================

DESCRIÇÃO: View principal para integração de alunos
OBJETIVO: Fornecer dados completos dos alunos para o sistema NPS

CAMPOS OBRIGATÓRIOS:
- ALUNO_ID           (NUMBER)     - ID único do aluno no TOTVS
- NOME               (VARCHAR2)   - Nome completo do aluno
- MATRICULA          (VARCHAR2)   - Número da matrícula
- EMAIL              (VARCHAR2)   - Email principal do aluno
- CURSO_ID           (NUMBER)     - ID do curso no TOTVS
- CURSO_NOME         (VARCHAR2)   - Nome do curso
- ATIVO              (NUMBER)     - Se o aluno está ativo (1) ou inativo (0)

CAMPOS OPCIONAIS:
- EMAIL_INSTITUCIONAL (VARCHAR2)  - Email institucional (se diferente)
- EMAIL_PESSOAL       (VARCHAR2)  - Email pessoal (se disponível)
- TELEFONE            (VARCHAR2)  - Telefone de contato
- CPF                 (VARCHAR2)  - CPF do aluno
- DATA_NASCIMENTO     (DATE)      - Data de nascimento
- CURSO_CODIGO        (VARCHAR2)  - Código do curso
- TURMA_ID            (NUMBER)    - ID da turma atual
- TURMA_NOME          (VARCHAR2)  - Nome da turma
- TURMA_ANO           (NUMBER)    - Ano da turma
- TURMA_SEMESTRE      (NUMBER)    - Semestre atual
- TURMA_PERIODO       (NUMBER)    - Período (1=Manhã, 2=Tarde, 3=Noite)
- FILIAL              (VARCHAR2)  - Nome da filial/unidade
- NIVEL_ENSINO        (VARCHAR2)  - Graduação, Pós, etc.
- PERIODO_LETIVO      (VARCHAR2)  - Período letivo atual
- STATUS_PERIODO      (VARCHAR2)  - Status no período letivo

EXEMPLO DE SELECT:
SELECT 
    ALUNO_ID, NOME, MATRICULA, EMAIL, EMAIL_INSTITUCIONAL, EMAIL_PESSOAL,
    TELEFONE, CPF, DATA_NASCIMENTO, CURSO_ID, CURSO_NOME, CURSO_CODIGO,
    TURMA_ID, TURMA_NOME, TURMA_ANO, TURMA_SEMESTRE, TURMA_PERIODO,
    FILIAL, NIVEL_ENSINO, PERIODO_LETIVO, STATUS_PERIODO, ATIVO
FROM VIEW_ALUNOS;

===============================================================================
                         OBSERVAÇÕES TÉCNICAS
===============================================================================

1. CAMPOS OBRIGATÓRIOS:
   - Nome, Email, Matrícula (para alunos), CPF
   - IDs únicos para todas as entidades
   - Campo de controle de ativo/inativo

2. CAMPOS OPCIONAIS:
   - Telefone, Data de Nascimento
   - Departamentos, Titulações
   - Informações de endereço para filiais

3. TIPOS DE DADOS:
   - IDs: NUMBER
   - Nomes/Textos: VARCHAR2(200) para nomes, VARCHAR2(500) para descrições
   - Datas: DATE ou TIMESTAMP
   - Status: NUMBER(1) para campos booleanos (0=Inativo, 1=Ativo)

4. ENCODING:
   - UTF-8 para caracteres especiais
   - Considerar acentuação em nomes brasileiros

5. PERFORMANCE:
   - Criar índices nas colunas de ID
   - Considerar particionamento por filial se necessário
   - Otimizar joins entre as views

6. SEGURANÇA:
   - Aplicar filtros de acesso por filial se necessário
   - Considerar views materializadas para melhor performance
   - Implementar controle de acesso por usuário do banco
